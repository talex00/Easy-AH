# aux — Classic 1.12.1 fixes (Фаза 0)

Сборка приведена к чистому WoW Classic 1.12.1 (без Turtle-специфики) + багфиксы и улучшения постинга.

## Сроки аукциона
- Подтверждено и зафиксировано: длительности = **2 / 8 / 24 часа** (`120 / 480 / 1440` минут — стандартные коды Blizzard 1.12).
- Метки дропдауна («2 Hours / 8 Hours / 24 Hours») и колонка Time Left (30m/2h/8h/24h) — classic.
- Числа 6/24/72 — это серверная особенность Turtle WoW (×3). Если вы их видели, у вас была Turtle-сборка; эта сборка показывает 2/8/24.
- В `tabs/post/core.lua` добавлен поясняющий комментарий к константам.

## Багфиксы
1. **Единицы ставки в записях аукционов** (`tabs/post/core.lua`): после постинга ставка записывалась как цена за весь стак вместо цены за единицу. Исправлено на per-unit.
2. **Запись автоцены**: при автоценообразовании (Unit Starting Price = 0) реальная цена считается внутри `core/post.lua` и не возвращается наружу — раньше в локальные записи попадал 0/мусор. Теперь при автоцене локальная запись не добавляется (нет искажения истории/списка).
3. **RNG для рандомных стаков** (`aux-addon.lua`): добавлен `math.randomseed(time())`. Раньше «рандомные» размеры стака повторялись каждую сессию (Lua 5.0).

## Улучшения
4. **Депозит через API сервера** (`tabs/post/core.lua`): вместо хардкода 5%/25% используется `GetAuctionHouseDepositRate()` (с фолбэком). Автоматически верно для фракционного/нейтрального АХ и серверов с изменёнными ставками.
5. **Настраиваемый undercut**: новая настройка `undercut` (по умолчанию 1 медь) вместо хардкода `−1`.
   - Команда: `/aux post undercut <медь>` (например `/aux post undercut 100` = подрезать на 1 серебро).
   - Значение видно в `/aux`.

## Убрана Turtle-специфика
6. **`aux-addon.lua`**: удалён хардкод реалма `Nordanaar → Horde` (форсил Horde-данные для RP-PvE реалма Turtle).

## Примечание по зависимости
- `OptionalDeps: ShaguTweaks` в `.toc` остаётся опциональной (используется как доп. источник вендор-цены в `core/post.lua`); на работу без неё не влияет.

# Фаза 1 — прозрачное и настраиваемое ценообразование

## Предпросмотр цен/прибыли в вкладке Post
- Внизу между кнопками — только `Deposit: X`.
- Справа от длительности (под ценой за штуку) — `Net if sold` (чистыми, минус комиссия АХ 5%/15% и депозит) и в режиме автоцены — `Auto: bid/buy` или рекомендация.
- Эвристика автоцены вынесена в общую `post.auto_price` (одинаковая логика для постинга и предпросмотра).

## Настраиваемые коэффициенты автоцены
- Все магические числа автоцены вынесены в `aux.account_data.autoprice` с дефолтами (`M.AUTOPRICE_DEFAULTS`).
- Команды:
  - `/aux post autoprice` — показать все коэффициенты и текущие значения.
  - `/aux post autoprice <key> <value>` — задать коэффициент (напр. `/aux post autoprice value_buyout 0.9`).
  - `/aux post autoprice reset` — сбросить к дефолтам.
- Ключи: value_buyout, daily_buyout, daily_start, merchant_buy_start, merchant_buy_buyout, vendor_base, vendor_amp, vendor_decay, vendor_flat, disenchant_start, bid_vs_buyout, de_reco_factor, de_reco_flat, vendor_reco.

## Робастный market value (опционально, по умолчанию — как раньше)
- `market_value` может считаться как нижний перцентиль активных лотов (взвешенный по количеству), а не единственный минимум — устойчиво к одиночному демпингу.
- По умолчанию выключено (`market_percentile = 0` = старое поведение — минимум).
- Команда: `/aux post marketpercentile <0-100>` (напр. `15` = 15-й перцентиль; `0` = выкл/минимум).
- Схема хранения истории НЕ изменена (совместимость со старыми сохранёнными данными).

# Фаза 2 — экономия времени

## Гибкий undercut
- Режимы подрезки: fixed (медь), percent (%), match (сравняться, не подрезать). Не подрезает свои лоты (было и раньше).
- Команды:
  - `/aux post undercut <медь>` — фиксированная подрезка (напр. `/aux post undercut 100` = 1 серебро).
  - `/aux post undercut percent <n>` — подрезать на n%%.
  - `/aux post undercut match` — ставить ровно как у минимального лота (без подрезки).
  - Цена не опускается ниже 1c.

## Явная стратегия стаков
- `/aux post stackmode max` — предлагать максимальный стак (по умолчанию).
- `/aux post stackmode random` — случайный размер стака (анти-снайп). Синхронизировано со старым `post stack`.

## Пакетный постинг «Post All»
- Новая кнопка **Post All** (справа от Refresh).
- Выставляет все НЕ скрытые аукционные предметы по их сохранённым настройкам (цена/длительность); если Unit Starting Price = 0 — работает автоцена.
- Стак: максимальный размер, максимальное кол-во стаков. Постит последовательно (переиспользует проверенный `post.start`).
- Прогресс в статус-баре; зарядовые предметы пока пропускаются (безопасность).
- Чтобы исключить предмет из Post All — отметь «Hide this item».

# Фаза 3 — надёжность и крайние случаи

## Безопасный unit_vendor_price
- Перед тем как брать предмет на курсор для чтения вендор-цены, проверяется `CursorHasItem()` — если на курсоре что-то есть, функция не трогает курсор (нет случайных подмен/выкладываний предметов).
- Больше НЕ прячет предмет молча (`hidden=true`) при неудаче чтения цены. Если вендор-цена неизвестна — депозит показывается как `Deposit: ?`, предмет остаётся в списке.

## Надёжный детект привязки
- `auctionable` теперь ищет маркеры привязки (BoP / Quest / Soulbound) по всем строкам тултипа (через `tooltip_match`), а не только во 2-й строке. Корректнее для предметов с «Unique»/доп. строками перед привязкой.

## Округление цен (опционально)
- `/aux post round` — вкл/выкл. При включении автоцена округляет bid/buyout до целого серебра для цен от 10s (дешёвые предметы не трогаются). По умолчанию выключено.

## Отложено
- Зарядовые предметы (масла и т.п.) в `stack.lua` + ценообразование за заряд — отдельным фокусным шагом (требует осторожной логики сборки зарядов и теста).

# Исправление + «не запоминать цену по умолчанию»

## Важный багфикс (регрессия)
- В `M.post_all()` вернулась ошибка «attempt to compare number with nil» (обращение к `settings.start_price` напрямую вместо защищённой локальной переменной). Снова исправлено.

## Новое: цена не «залипается» по умолчанию
- Новая настройка `remember_prices` (по умолчанию **выкл**).
- Когда выключено (по умолчанию):
  - При каждом выборе предмета во вкладке Post цена сбрасывается на 0 (автоцена) — никаких старых «zastyvshih» значений.
  - `Post All` тоже игнорирует сохранённые ручные цены и всегда автоценит каждый предмет, если настройка выключена.
- Когда включено: всё как раньше — ручная цена/выбор лота сохраняются между выборами предмета.
- Команда: `/aux post remember` (тоггл). Чекбокс «Remember manual prices per item» в вкладке Settings.

# Post All теперь поддерживает зарядовые предметы

- Зарядовые предметы (масла, прицелы и т.п.) нельзя объединить/разбить как обычные стаки — это ограничение игры, не аддона.
- Теперь `Post All` автоматически находит все реально существующие группы одинаковых по числу зарядов в сумках и выставляет каждую отдельным лотом (напр. 2 масла по 5 зарядов + 1 с 3 зарядами = 2 разных лота).
- Цена за заряд берётся из тех же сохранённых настроек предмета (или автоцена, если `remember_prices` выключен) и умножается на число зарядов конкретного лота при выставлении (как и раньше для ручного постинга одного предмета).
- Обычные предметы постятся как раньше (максимальный стак).

# Шаг 3 из 3 — визуальный рескин под Blizzard

Все базовые элементы в `gui/core.lua` переведены с плоских одноцветных текстур (стиль TSM) на родные текстуры/шаблоны Blizzard. Так как все вкладки переиспользуют эти общие функции, рескин применился сразу ко всему аддону (Search, Post, Auctions, Bids, окно настроек).

- **Окна/панели**: `set_window_style` теперь использует `Interface\DialogFrame\UI-DialogBox-Background/Border` (та же текстура, что у стандартных диалогов Blizzard). `set_panel_style` — `Interface\Tooltips\UI-Tooltip-Background/Border`. `set_content_style` — `Interface\Common\Common-Input-Border`.
- **Кнопки**: родной `UIPanelButtonTemplate` (золотая рамка, как у стандартных кнопок в игре) вместо плоской цветной подложки. Состояние вкл/выкл теперь рисуется нативно (без ручных перекрасок).
- **Чекбоксы**: родной `UICheckButtonTemplate` с родной галочкой/рамкой вместо плоского квадрата.
- **Дропдауны**: восстановлены родные текстуры Left/Middle/Right (раньше скрывались ради плоского вида); ширина теперь корректно меняется через `UIDropDownMenu_SetWidth` (вызывается автоматически, вызовы `:SetWidth(n)` не менялись).
- **Слайдеры**: родной `OptionsSliderTemplate` (желобок-бегунок + ползунок) вместо тонкой кастомной полоски. Внешний API (`slider.label`, `slider.editbox`) не изменился, все существующие вызовы в Settings работают без изменений.
- Найдена и исправлена 1 регрессия: кнопка «Resume» в Search красилась в зелёный через `SetBackdropColor` — у новых кнопок нет бэкдропа, поэтому подсветка переделана через цвет текста.

⚠️ **Важно**: это визуальные изменения, которые невозможно отрендерить в песочнице без клиента WoW. Текстуры и шаблоны — стандартные и широко используемые в аддонах 1.12, но точный вид (отступы, размеры) нужно проверить вживую и сообщить, что выглядит не так — доправлю по скриншотам.

# Защита от слишком тонкого рынка + поиск похожих предметов

Проблема: для редких/малоликвидных предметов (напр. кольцо 16 уровня, где на аукционе всего 1-2 реальных лота) авто-цена и раньше, и после водопадного рефакторинга уверенно ставила цену по этим 1-2 лотам, хотя это не настоящий рынок, а случайные ставки.

- **core/history.lua**: рядом с рыночным минимумом (`session_market`) теперь хранится и число конкурирующих (не своих) лотов, на основе которых он посчитан (`session_market_count`, `M.market_count(item_key)`). `M.set_market_value` принимает необязательный третий параметр `count`.
- **core/post.lua** (`auto_price`): новый предохранитель — если базовая цена взята из рыночного источника, а число конкурирующих лотов меньше `min_market_sample` (по умолчанию 3), статус становится `review_thin_market` вместо уверенного авто-выставления. И вручную (Post), и в Post All такой лот пропускается с просьбой проверить вручную.
- **Новый коэффициент** `min_market_sample` в Settings → Advanced Auto-Price Coefficients (0 = выключить проверку).
- **tabs/post/core.lua / frame.lua**: при статусе `review_thin_market` для брони и оружия (Weapon/Armor) появляется кнопка **Similar Items** — она строит запрос по тому же классу/подклассу/слоту, диапазону уровня (±2) и качеству и открывает вкладку Search с готовым фильтром, чтобы вручную оценить цену по более широкой категории (как игрок сам сравнивает похожие кольца/оружие по уровню). Для расходников/реагентов/рецептов кнопка не показывается — там сравнение по категории не имеет смысла.
